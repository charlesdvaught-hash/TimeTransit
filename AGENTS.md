# AGENTS.md — TimeTransit

## What this is

A map-first, key-free transit explorer. It ranks nearby places by real
door-to-door journey time (walk + wait + ride + transfers), not distance.
Single-page Vite + React 19 + TypeScript app; **no backend, no accounts**.
All persistent state lives in `localStorage`. Optional Transit API
(transitapp.com) integration adds live departure ETAs to selected journeys.

## Commands

On Windows use `npm.cmd` / `npx.cmd` (the Git Bash npm shim is unreliable here).

- `npm install`
- `npm run dev -- --port 5173`
- `npm run build` — `tsc -b && vite build`; emits an installable PWA to `dist/`
- `npx vitest run` — unit tests; two live-API suites skip unless `LIVE=1`
- `npx prettier --check .` / `npm run format` — formatting is enforced

Verify any change with `npx.cmd tsc -b` + `npx.cmd vitest run` before calling it done.

## Environment

`.env.local` (gitignored; `.env*` is in `.gitignore` — do not bypass that):

- `VITE_TRANSIT_API_KEY` — Transit app API key (docs: api-doc.transitapp.com).
  Stamped onto requests by the dev proxy; never reaches the bundle.
- `VITE_TRANSIT_RELAY` — production relay URL (Cloudflare Worker). When set,
  the client calls it directly instead of `/transit`. Empty → `/transit` dev proxy.
- `VITE_TOMTOM_API_KEY` — TomTom Search key for the automatic place fallback.
  Client-visible by design; restrict it by domain whitelist (CORS) and the
  Search product in the TomTom key settings. Absent → fallback silently off.
- `VITE_GOOGLE_EMBED_KEY` — optional Google Maps Embed key; when set,
  `GmapsLink` gains an "in-app" button that opens the place in an iframe
  overlay. Absent → link-only mode. Client-visible; restrict by HTTP
  referrer in Google Cloud console.
- `VITE_BASE` — optional Vite base path override for the production build.
  **Git Bash trap:** prefix-assigning it (`VITE_BASE=/TimeTransit/ npm run build`)
  gets MSYS path-converted into `Program Files/Git/TimeTransit/` — the Pages
  deploy then 404s every asset. Use `MSYS_NO_PATHCONV=1` or `MSYS2_ARG_CONV_EXCL`
  on the same command, then confirm `dist/index.html` says `/TimeTransit/`.
  Defaults to `/TimeTransit/` (GitHub Pages project path). Set before
  `npm run build` if hosting elsewhere.

Worker env (never bundled; secrets via `wrangler secret put`, plain values as
`[vars]` in `worker/wrangler.toml`):

- `GROQ_API_KEY`, `GEMINI_API_KEY` — LLM provider secrets for `POST /llm`.
- `SEATGEEK_CLIENT_ID` — free SeatGeek client id for `GET /events`. Absent →
  the route still serves the keyless sources (lacity, santamonica, mobilizon).
- `GMAPS_API_KEY` — Google Places key for `GET /gmaps/*` (restrict by HTTP
  referrer in the Google Cloud console).
- `LLM_PROVIDERS` — comma-separated fallback order, default and deployed
  `groq,gemini` (probe: Groq 19/20 schema-valid @ ~0.5 s, Gemini ~10/20 with
  intermittent 403/503 — Gemini is the fallback, not the primary).
- `TRANSIT_API_KEY`, `ALLOWED_ORIGINS` — existing Transit relay config.

## Conventions

- **Secrets never ship**: only `VITE_*` vars reach the bundle; the Transit key
  lives server-side (dev proxy or Worker env secret). `.env*` is gitignored —
  edit it via shell if tooling refuses.
- **No synthetic fallbacks**: public services fail visibly; missing data fields
  are never invented. Transit features degrade silently (the app predates the key).
- **Compact code**: terse TS matching surrounding style; no explanatory comments.
- **Pure logic in `core.ts`/`transit.ts` matchers**, React/network at the edges —
  that's what makes it testable. Keep it that way.
- **Tests mock `fetch`** (vitest `vi.spyOn`). `api.ts`'s module-level cache
  persists across tests in one file — use distinct queries/origins per test.
- Guard every browser API (`localStorage`, `geolocation`, `AbortSignal`) —
  tests run without a DOM.

## Verified facts (receipts, don't re-derive)

- Transit API v4: `https://external.transitapp.com/v4/public/*`, `apiKey` header.
  Gateway (Kong) returns **no CORS headers** even on 401 — verified via
  OPTIONS + GET probes; a relay is required for browser use.
- Photon `q=` matches **names only**; `include=osm.<key>.<value>` filters by
  tag. This is why the fuzzy matcher exists — "Walmart" never contains "grocery".
- MOTIS v2 plan geometry uses polyline precision 6 (v1's precision-7 is
  undefined beyond 107° longitude).
- Esri World Imagery and World\_Boundaries\_and\_Places raster tiles are
  key-free and CORS-enabled; they back the satellite basemap and require visible
  attribution.
- MOTIS `one-to-all` returns `duration` in minutes and takes `maxTravelTime` in
  minutes. The experimental `map/routes` endpoint is far too heavy for viewport
  fetching (~800 kB / 9 s at zoom 13), so corridor glow uses planned leg
  geometry instead.
- Cloudflare Workers free plan: 100k requests/day — far above this relay's load.
- Transit API free tier: 5 calls/min. A live alternative comparison costs ~3
  calls (two boarding-stop lookups + one batched stop_departures — a 20-stop
  batch consumes 1 per-minute quota unit, verified by Remaining-Minute 5→4 in
  one window), so it is capped at two alternatives and throttled to one
  comparison per 60 s. No monthly-quota header exists; count locally.
- `stop_departures` accepts comma-separated `global_stop_id`s (≤100 documented)
  and a `time` UNIX param; ~2 h ahead returns schedule-only (`is_real_time:false`).
- Transit `global_stop_id` is `NETWORK:<internal id>` (e.g. `OCTA:64862` for
  Haster-Orangewood) and the suffix is NOT the GTFS `stop_id` (`0002`) — it
  can't be synthesized from the index, so the `nearby_stops` lookup stays.
- OCTA GTFS: `octa.net/current/google_transit.zip` ~4 MB — 5,269 stops, 56
  routes, 7,243 trips, 453,744 stop_times; `shapes.txt` present, `frequencies.txt`
  absent. Feed window ends 2027-02-13; regenerate `public/scan/octa.json` via
  `scripts/build-scan-index.mjs`. Index ≈3.4 MB (5,269 stops / 146 patterns /
  7,243 trips / 9,946 walk links).
- OCTA GTFS-RT at `api.octa.net/GTFSRealTime/protoBuf/*.aspx` is keyless protobuf
  (wrongly labeled text/html) with **no CORS** — relayed at `/gtfsrt/*` (dev
  proxy + `worker/transit-relay.js`), decoded by `src/gtfsrt.ts`. Swiftly
  mirrors need a key (401).
- Scan-vs-MOTIS spot check (Nov 2026, Anaheim→Santa Ana): scan 66 min vs MOTIS
  68 min — 1.4 min gap. Run `LIVE=1 npx vitest run src/spotcheck.test.ts`.
- Transitous rejects the default Node fetch user-agent with 403 — set a
  `User-Agent` header in any Node-side probing.
- Groq `openai/gpt-oss-20b` structured output (verified against Groq docs):
  `response_format: {type:"json_schema", json_schema:{name, strict:true,
schema}}`, `reasoning_effort:"low"`, `include_reasoning:false`,
  `temperature:1`, `top_p:1`, `max_completion_tokens:1024`. Strict mode wants
  every property in `required` (optional fields as `["type","null"]` unions)
  and `additionalProperties:false` on every object.
- Gemini `gemini-3.5-flash-lite` generateContent: `response_mime_type:
"application/json"` + `response_json_schema` + `thinking_level:"minimal"`.
  Do NOT send temperature/top_p/top_k — deprecated for this model. The schema
  must be the OpenAPI-3.0 subset: no `additionalProperties`, no `["type",
"null"]` unions — the worker strips them via `geminiSchema()`.
- TomTom Search API legacy (v2) free tier is **2,500 requests/month**, no card
  (Places Search API v3 is 10k Suggest + 5k Discover + 5k Details/month). The
  older platform FAQ's "2,500 non-tile per day" is outdated — pricing page wins.
- TomTom fuzzy search returns `results[].position.lat/lon` directly, so a
  suggestion is already a pinnable place; TomTom places are keyed `tomtom-<id>`
  and shown with “Places © TomTom”.
- MOTIS plans transfers at every served stop, including stops at intersections;
  the app never invents a transfer at an intersection without a stop.
- **Production deploy (live since Nov 2026)**: GitHub Pages at
  `https://charlesdvaught-hash.github.io/TimeTransit/` from the `gh-pages`
  branch — redeploy = `npm run build` + `npx gh-pages -d dist -b gh-pages`.
  Pages on the free plan requires the repo to stay **public** (verified via
  API 422 when private). Build order matters: `VITE_TRANSIT_RELAY` in
  `.env.local` is baked at build time, so it must be set _before_ building.
- Git identity is unset on this machine — pass `-c user.name=... -c
user.email=...` per commit, and `GIT_AUTHOR_*`/`GIT_COMMITTER_*` env vars
  for `npx gh-pages` (it spawns plain `git commit`).

## Transit API terms (transitapp.com/reports/API_terms.pdf — read before shipping)

- Public apps are explicitly allowed (§2.2 grants rights to "distribute a
  Partner Application" serving End Users), but §2.1 restricts the free tier to
  "testing purposes or small-scale use" — real public scale requires an API
  Agreement (paid, negotiated with Transit).
- **Free-tier limits (§2.4): 5 calls/min, 1,500 calls/month** — hard ceiling,
  auto-suspension on breach. ~1–2 calls per transit leg per selection means
  this feeds a demo, not a user base.
- **§3.1: notify Transit ≥10 business days before** making the app public;
  they may require integration changes first. Not needed for limited testing.
- **§3.2: "Powered by Transit" logo** must visibly appear wherever API Data is

## Watch out

- Transit free-key quota is 5 calls/min + 1,500 calls/month (see terms above);
  each journey selection costs ~1–2 relay requests per transit leg, and the
  alternative comparison is throttled to stay under the per-minute ceiling.
- Each Explore search adds one MOTIS `one-to-all` request (cached per
  origin + departure); it is bounded with a 2.5 s race and falls back to
  distance order, so a slow reachability query never blocks results.
- Service worker caches app shell, dark and satellite basemap tiles, fonts;
  plan/search data is NetworkFirst with 24 h fallback; Transit API responses are
  deliberately uncached.
- Geolocation needs a secure context (HTTPS or localhost) — the installable PWA
  must be served over HTTPS.
- `npm install` may warn about esbuild's postinstall under allow-scripts —
  harmless for local dev.
- `runExplore` honours a pinned place for the exact searched text (that is how a
  TomTom suggestion becomes a destination despite OSM having no such business);
  without the pin it re-searches the term against Photon as before.
- `MultiStopPlanner.tsx` was removed when `+` syntax replaced the tab UI; don't
  resurrect it — extend the single search box instead.

## OneBusAway plan (Nov 2026 — decided, not built)

- **What:** self-hosted OneBusAway (`github.com/OneBusAway`) as a SoCal
  realtime layer — goal is removing the Transit free-tier release blocker
  (1,500 calls/mo hard cap; paid agreement needed for real scale).
- **Coverage:** hosted regions have NO LA/OC
  (`regions.onebusaway.org/regions-v3.json` — San Diego closest, plus
  Tampa/Puget Sound/DC/Adelaide/Davis; MTA NY is SIRI-only) → self-host is
  required for home turf.
- **API receipts:** CORS `Access-Control-Allow-Origin: *`; `key=TEST` works
  but is shared/rate-limited; `arrivals-and-departures-for-location` = one
  call for every predicted arrival in a radius; `trip-details` status
  carries position, orientation, `scheduleDeviation`,
  `occupancyStatus`/`Count`/`Capacity`, and `nextTripId`/`previousTripId`
  (block chaining); `vehicles-for-agency`; official npm SDK
  `onebusaway-sdk`.
- **Deploy:** `github.com/OneBusAway/docker` — compose includes its own
  mysql:8.4 AND postgres:16 (whole stack = one Docker host); builds OBA
  2.7.2 from source so ARM works; `GTFS_RT_FEEDS` env is a JSON array of
  feeds `{tripUpdatesUrl, vehiclePositionsUrl, alertsUrl, agencyIds[]}` →
  OCTA + Metro realtime in one deploy; static `GTFS_URL` is single-feed →
  OCTA-only v1.
- **Host (decided, not provisioned):** Oracle Cloud Always Free Ampere A1
  (up to 4 OCPU / 24 GB / 200 GB, free public IPs, ~10 TB/mo egress; prefer
  us-sanjose-1/us-phoenix-1; signup card is refunded; idle-reclaim risk →
  watchdog ping doubles as keep-alive).
- **Ops robot:** Devin automation (or public-repo GH Actions — free) does
  weekly GTFS bundle rebuild + health watchdog; GTFS drift matters (OCTA
  feed expires 2027-02-13).
- **Accuracy scoreboard (planned):** provider-tagged prediction-vs-actual
  table in `ReliabilityPanel`; observations already dedupe by source so a
  new provider is a new tag; log store = worker D1/KV — never an external
  hosted DB for OBA (its DB is rebuildable scratch).
- **Metro realtime:** `api.metro.net` is keyless JSON but real-time
  endpoints return `[]` and send no CORS → Metro RT path is Swiftly
  (`api.goswift.ly`, free key; OBA supports `FEED_API_KEY` header).
- **Rejected:** GCP e2-micro (external IPv4 ~$3.65/mo breaks $0), home-PC
  hosting (~$20-35/mo electricity, inefficient), external hosted OBA DB
  (scratch state), local Docker (personal PC stays out of the loop).
  OBACloud (OTSF managed) = fallback if ops ever annoys.
- **Integration sketch (unbuilt):** worker `/oba/*` relay (key inject +
  origin allowlist) → LiveProvider-style interface over `src/transit.ts` →
  hosted-region dispatch for covered cities later.

Nothing above is built — live ETAs today still come from `src/transit.ts`
(Transit API relay) and `src/gtfsrt.ts` (OCTA feed). Full decision trail:
`onebusawaybrainstorm.txt` (repo root).
