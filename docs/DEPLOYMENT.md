# Deployment

TimeTransit has three deployable pieces, all optional except the static app:

| Piece                     | What it is                                                                                                   | Needed for                                                                                      |
| ------------------------- | ------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------- |
| `dist/` (build output)    | The PWA itself — static files                                                                                | Any deployment                                                                                  |
| `worker/transit-relay.js` | Cloudflare Worker: key injection, keyless-feed relay, LLM, events, Google Places, KV sync, MOTIS passthrough | Live ETAs outside dev, AI features, events, enrichment, cross-device sync on self-hosted builds |
| `site/index.js`           | Cloudflare Worker: gated host — Cloudflare Access + static assets + per-user `/api/state`                    | The hosted instance only                                                                        |

None of them is a backend in the classic sense: the app works from static
hosting alone; each Worker adds integrations on top.

## The static app (`dist/`)

`npm run build` → `dist/` (manifest, icons, service worker generated by
`vite-plugin-pwa`). Serve from any HTTPS host — geolocation requires a secure
context (HTTPS or localhost), and the PWA install path needs HTTPS too.

**Base path.** `vite.config.ts` reads `VITE_BASE`, defaulting to
`/TimeTransit/` (the GitHub Pages project path). Set it before building for
any other host — e.g. `VITE_BASE=/` for an apex workers.dev site — and confirm
`dist/index.html` references the right prefix.

> **Git Bash trap (Windows):** prefix-assigning `VITE_BASE=/ npm run build`
> gets MSYS path-converted into `/Program Files/Git/` and every deployed asset
> 404s (black screen). Use `MSYS_NO_PATHCONV=1 VITE_BASE=/ npm run build` or
> `MSYS2_ARG_CONV_EXCL` on the same command.

**Build-time config.** `VITE_TRANSIT_RELAY`, `VITE_TOMTOM_API_KEY`, and
`VITE_GOOGLE_EMBED_KEY` from `.env.local` are baked into the bundle at build
time — set them **before** `npm run build`, then rebuild to change them.

## Transit relay (`worker/transit-relay.js`)

A standalone Cloudflare Worker. Deployed instance:
`transit-relay.charlesdvaught-34c.workers.dev`. Free plan (100k req/day) is far
above its load.

### Routes

| Route                                   | Upstream                                                                                                            | Notes                                                                                                                                                  |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `/v4/*`                                 | `external.transitapp.com`                                                                                           | Injects `apiKey` secret (`TRANSIT_API_KEY`)                                                                                                            |
| `/gtfsrt/*`                             | `api.octa.net/GTFSRealTime/protoBuf/*.aspx`                                                                         | Keyless; last-good feed shield serves a stale cache on upstream failure and sets `x-feed-stale`                                                        |
| `POST /llm`                             | Groq → Gemini fallback                                                                                              | In-worker prompts + strict JSON schemas (`parse`, `rank`, `assist`); one retry per provider on 403/429/5xx; 30 req/min/IP + 800 req/day in-memory caps |
| `GET /gmaps/text`, `GET /gmaps/details` | Google Places                                                                                                       | Text Search returns IDs only (50 km `locationBias` from `?lat&lon`); details = rating/count/priceLevel/openNow; 20 req/min/IP + 850 req/month caps     |
| `GET /events?lat&lon&start&end&q`       | SeatGeek + LA Socrata `9aw9-mn4p` + Santa Monica CKAN `a8ecb913` + Mobilizon GraphQL + curated Eventbrite OC venues | Merged/sorted/capped at 40; 10 req/min/IP + 400 req/day; missing sources fail quietly; ~6 h in-worker Eventbrite cache (`EB_VENUES` seed list)         |
| `GET /eb/event`                         | Eventbrite                                                                                                          | Single-event lookup for event stops                                                                                                                    |
| `GET/PUT /api/state`                    | `TT_STATE_KV`                                                                                                       | Bearer-token KV sync (`TT_SYNC_TOKEN` secret); 503 without the secret — expected, not an error                                                         |
| `POST /api/board`                       | MOTIS                                                                                                               | Edge-fanned bookmark ETAs                                                                                                                              |
| `GET /api/nearby`                       | MOTIS                                                                                                               | Stops + departures near a point                                                                                                                        |
| `POST /api/plan`                        | MOTIS                                                                                                               | Translated to GET upstream (MOTIS is GET-only)                                                                                                         |
| `GET /api/arrivals`                     | OCTA GTFS-RT                                                                                                        | Edge-decoded arrivals, OBA-shaped response                                                                                                             |
| `GET /api/health`                       | —                                                                                                                   | Upstream health from the 5-min cron watchdog probe → KV                                                                                                |
| `GET /api/probe`                        | —                                                                                                                   | Debug probe                                                                                                                                            |

All LLM prompts and schemas live in the worker — never client-supplied. The
`assist` schema constrains `depart_at`/`return_by` to a rolling ~62-day window
via a `pattern`; Groq enforces it at token level, Gemini honors it as guidance
(client-side `fresh()` drops leaks). Rate caps are in-memory — they reset on
worker eviction, which is fine for this scale.

### Configuration (`worker/wrangler.toml`)

```toml
name = "transit-relay"
main = "transit-relay.js"

[triggers]
crons = ["*/5 * * * *"]        # upstream watchdog probe → TT_STATE_KV

[vars]
ALLOWED_ORIGINS = "http://localhost:5173, https://your-app.example"
LLM_PROVIDERS = "groq,gemini"  # fallback order

[[kv_namespaces]]
binding = "TT_STATE_KV"
id = "…"
```

**Secrets** (via `npx wrangler secret put NAME`, or `worker/.dev.vars`
locally — gitignored): `TRANSIT_API_KEY`, `GROQ_API_KEY`, `GEMINI_API_KEY`,
`GMAPS_API_KEY`, `SEATGEEK_CLIENT_ID`, `EVENTBRITE_API_KEY`, `TT_SYNC_TOKEN`.

`ALLOWED_ORIGINS` is the quota-theft protection: the worker echoes the request
`Origin` only when allowlisted, so a stranger finding the URL can't drive it
from a browser.

### Deploy

```bash
cd worker
npx wrangler deploy
npx wrangler secret put TRANSIT_API_KEY   # and any others
```

The Cloudflare dashboard's drag-upload refuses JS projects — use the CLI.
To deploy independently of this repo, paste `transit-relay.js` into a new
Worker and set the same vars/secrets.

## Hosted site (`site/index.js`)

The gated production host at
`https://timetransit-site.charlesdvaught-34c.workers.dev`. It fronts `dist/`
with two independent gates and answers `/api/state` per user.

- **Cloudflare Access (primary).** An email-OTP allowlist policy fronts the
  whole hostname. The verified email arrives as `Cf-Access-Authenticated-Email`
  or inside the `CF_Authorization` JWT cookie (the worker decodes, not verifies,
  the payload — presence implies Access already admitted the request). Access
  keeps a 30-day session. Adding testers = updating the Access policy's
  `include` list.
- **Shared-secret fallback.** `?key=SITE_KEY` sets a 30-day `tt_gate` cookie;
  anything else gets a flat 404 — the site is indistinguishable from
  nonexistent to casual discovery. `SITE_KEY` is a wrangler secret, not in the
  repo.
- **`/api/state`.** `GET/PUT` a single JSON blob per user in `TT_STATE_KV`,
  keyed `state:{email}` (or `state:shared` under the key gate).
  `src/syncClient.ts` auto-configures sync on this origin — no Settings entry
  needed.
- **`run_worker_first = true` is required.** Without it the assets binding
  bypasses the worker entirely and the gates don't run.

`site/wrangler.toml`:

```toml
name = "timetransit-site"
main = "index.js"

[assets]
directory = "../dist"
binding = "ASSETS"
run_worker_first = true

[[kv_namespaces]]
binding = "TT_STATE_KV"
id = "446d050b6f8a42b1acd7d8ca00214f1c"
```

Deploy (build first, with the right base and relay):

```bash
MSYS_NO_PATHCONV=1 VITE_BASE=/ npm run build
cd site && npx wrangler deploy
```

## Hosted vs self-hosted

| Capability                                    | Hosted (workers.dev + relay + site) | Self-hosted (`dist/` only) | Self-hosted + own relay         |
| --------------------------------------------- | ----------------------------------- | -------------------------- | ------------------------------- |
| Core explore + multi-stop planning            | ✓                                   | ✓                          | ✓                               |
| Saved places, recents, favorites, share links | ✓                                   | ✓                          | ✓                               |
| Live departure ETAs                           | ✓ (Transit API)                     | — (schedule only)          | ✓                               |
| OCTA GTFS-RT delays + alerts                  | ✓                                   | — (feed has no CORS)       | ✓                               |
| AI modes, adventure assistant                 | ✓                                   | —                          | ✓                               |
| Events, Google Places details                 | ✓                                   | —                          | ✓                               |
| Cross-device sync                             | ✓ (auto, per Access email)          | —                          | ✓ (Settings → Sync URL + token) |
| Email gate / accounts                         | ✓ (Cloudflare Access)               | —                          | —                               |

Visitors to the hosted app need no keys and no clone. A self-host deployer
configures only the pieces they want; everything else degrades cleanly.

## Going public

GitHub Pages was disconnected (the `gh-pages` branch was deleted; the Pages
API refuses deactivation with 422). Two public paths:

1. Rebuild with the default `VITE_BASE=/TimeTransit/` and
   `npx gh-pages -d dist -b gh-pages`. (Needs git identity env vars —
   `GIT_AUTHOR_*`/`GIT_COMMITTER_*` — since `gh-pages` spawns plain
   `git commit`.)
2. Remove the email allowlist from the Access policy and keep the Workers
   host. Review [API-INTEGRATIONS.md](API-INTEGRATIONS.md#transit-api-terms)
   first — the Transit API free tier does not scale to a public user base.

## KV storage

One namespace, `TT_STATE_KV`, bound in both workers (the deployed relay and
site share id `446d050b6f8a42b1acd7d8ca00214f1c`). It holds per-user sync blobs
(`state:{email}` / `state:v1` / `state:shared`) plus cron watchdog health.
Local storage remains primary; KV is a mirror. See
[DATA-AND-PRIVACY.md](DATA-AND-PRIVACY.md#synchronization).
